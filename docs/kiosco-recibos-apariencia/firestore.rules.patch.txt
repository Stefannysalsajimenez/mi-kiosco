PARCHE APLICADO POR EL INSTALADOR A firestore.rules
====================================================

El instalador intenta realizar únicamente estos cambios sobre las reglas actuales:

1. Validar al administrador comparando el teléfono autenticado con config/admin.phones.
2. Permitir que el administrador actualice documentos config/theme, config/billing y config/payments.
3. Mantener config/admin legible para el flujo actual de autenticación por teléfono.
4. Permitir lectura pública de orders para conservar el seguimiento sin cuenta solicitado por el proyecto.

Bloque recomendado para isAdmin():

function isAdmin() {
  return request.auth != null
    && request.auth.token.phone_number != null
    && request.auth.token.phone_number in get(
      /databases/$(database)/documents/config/admin
    ).data.phones;
}

Bloque recomendado para config:

match /config/{docId} {
  allow read: if true;
  allow write: if isAdmin();
}

Bloque recomendado para orders:

match /orders/{orderId} {
  allow create: if request.resource.data.keys().hasAll(['items', 'total', 'status', 'createdAt'])
    && request.resource.data.status == 'pending'
    && request.resource.data.total is number
    && request.resource.data.total > 0
    && request.resource.data.items is list
    && request.resource.data.items.size() > 0;
  allow read: if true;
  allow update, delete: if isAdmin();
}

ADVERTENCIA DE PRIVACIDAD
-------------------------
La lectura pública de orders permite el seguimiento sin Firebase Auth, pero no constituye
un control de identidad. Un nombre o teléfono no es un secreto. Para privacidad fuerte,
el sistema debe migrar a enlaces aleatorios por pedido o autenticación de clientes.

Antes de desplegar revise el diff:

git diff -- firestore.rules storage.rules

Luego despliegue únicamente reglas:

npx firebase-tools deploy --only firestore:rules,storage
